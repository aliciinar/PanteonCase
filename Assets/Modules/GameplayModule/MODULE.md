# GameplayModule

## Purpose
Owns the gameplay side of a run. The game is played one action at a time: `RD_GameStatus` (in `Modules.Gameplay.Shared`, filed in the Shared Scriptables of GameplaySystemRoot's adapter) says whether an action - a unit walking out of its door, walking to a cell, or walking up to strike - is running. Only this module writes it (`internal` setter, `InternalsVisibleTo("Modules.Gameplay")`): `Incoming.Lock` / `Unlock` (the units module's `ActionStarted` / `ActionEnded`) → `SetGameLockCommand`. Every module that takes an order reads it through `ISharedDataModel` in its own model and leaves orders unanswered while it is locked: Input announces no press, Buildings picks, places and drops nothing, Units makes no unit. `GameStatusModel` unlocks it when a session starts and ends - the asset keeps its values between Editor play sessions.
