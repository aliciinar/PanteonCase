# PopupScreen

## Purpose
A generic message popup over every other screen: any module's signal opens it with a message, and a click on the dimmed panel behind it closes it.

It belongs to ScreenModule because it shows no one module's feature: whoever has something to tell the player connects its own announcement to `Incoming.ShowPopup(string)` in a Connector, and the message text is the sender's (Units reads its refusals from CD_Units). `ShowPopupCommand` opens the screen (layer 7 - over the HUD, under the loading screens) and writes the message; a message while it is open replaces the one it shows. The prefab: `Backdrop` (full-screen black at 55 % alpha, a `Button` with no transition - the only raycast target) and `Panel` (an amber frame, `Body`, the white Kenney warning sign tinted amber - `Art/Warning.png`, CC0 Game Icons pack, in the UI atlas - the `Message` and a "Click anywhere to close" hint), none of which takes a click, so a click anywhere reaches the backdrop. The panel pops in (`DOScale`, OutBack, unscaled time); the screen takes clicks only once it has. How it pops - `PopDuration`, `PopFromScale` - is `CD_PopupScreen` (`Scriptables/`, filed in the Scriptables of ScreenRoot's RootAdapter, the Root the context is listed on; the test scene files it on PopupTestRoot). `PopupScreenModel` reads it; `ShowPopupCommand` hands it to the screen with `SetParameters(PopupAnimationVO)`, because the animation plays inside `Show()` - before the command has the view - and the view reads it in `BeforeScreenActivation`.

## Decisions
- Dismissing decides nothing, so the Mediator calls `_view.Hide()` itself, guarded by `AvailableToSendSignal`.
- The game is not locked while it is up (user decision): the backdrop covers the whole screen, so nothing under it can be clicked, and the click on it only closes it. It announces nothing.

## Known gaps
- The click that closes it is a press over UI to Input (`PointerPressedOverUI`), which clears a selected unit like any other UI press.
