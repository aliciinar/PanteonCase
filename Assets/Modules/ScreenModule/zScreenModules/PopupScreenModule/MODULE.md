# PopupScreen

## Purpose
A generic message popup over every other screen: any module's signal opens it with a message, and a click on the dimmed panel behind it closes it.

It belongs to ScreenModule because it shows no one module's feature: whoever has something to tell the player connects its own announcement to `Incoming.ShowPopup(string)` in a Connector, and the message text is the sender's (Units reads its refusals from CD_Units). `ShowPopupCommand` opens the screen (layer 7 - over the HUD, under the loading screens) and writes the message; a message while it is open replaces the one it shows. The prefab: `Backdrop` (full-screen black at 55 % alpha, a `Button` with no transition - the only raycast target) and `Panel` (an amber frame, `Body`, the `Icon` - the white Kenney warning sign coloured amber, `Art/Warning.png`, CC0 Game Icons pack, in the UI atlas - the `Message` and a "Click anywhere to close" hint), none of which takes a click, so a click anywhere reaches the backdrop. The panel pops in (`DOScale`, OutBack, unscaled time); the screen takes clicks only once it has. Its icon and how it pops - `Icon`, `PopDuration`, `PopFromScale` - are `CD_PopupScreen` (`Scriptables/`, filed in the Scriptables of ScreenRoot's RootAdapter, the Root the context is listed on; the test scene files it on PopupTestRoot). `PopupScreenModel` reads it; `ShowPopupCommand` hands it to the screen with `SetParameters(PopupStyleVO)`, because the animation plays inside `Show()` - before the command has the view - and the view sets the icon and reads the animation in `BeforeScreenActivation`.

## Decisions
- **The prefab references no sprite.** `PopupScreen` is addressable and its icon lives in the UI atlas, which is not; a prefab in a bundle that references a sprite of a non-addressable atlas makes Addressables copy the whole atlas texture into that bundle (Addressables docs, "Sprite prefabs in a non-Addressable SpriteAtlas"). The icon is set from CD_PopupScreen as the screen opens, as ProductionMenu and InfoScreen set theirs from their configs.
- Dismissing decides nothing, so the Mediator calls `_view.Hide()` itself, guarded by `AvailableToSendSignal`.
- The game is not locked while it is up (user decision): the backdrop covers the whole screen, so nothing under it can be clicked, and the click on it only closes it. It announces nothing.

## Known gaps
- The click that closes it is a press over UI to Input (`PointerPressedOverUI`), which clears a selected unit like any other UI press.
